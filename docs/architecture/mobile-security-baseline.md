# 移动端安全基线

**状态：R1 已锁定，生产发布门禁。**

本基线解决 UniClip 与 SyncClipboard v3 参考实现中存在的明文凭据、明文历史和仅依赖 HTTP Basic Auth 的风险。凡与旧文档或旧实现冲突之处，以本基线和 `VISION.md` 的“持久化即密文”原则为准。

## 威胁模型

保护范围包括同一局域网中的被动监听者、恶意热点、日志与备份泄露、移动设备文件系统被离线读取，以及配对二维码被短暂拍摄。首版不承诺抵御已完全控制且已解锁设备的攻击者。

## 强制门禁

| 编号 | 要求 | 首个生产版验收条件 |
| --- | --- | --- |
| M1 | 凭据安全存储 | iOS 使用 Keychain/Access Group；Android 使用 Keystore 包装密钥。配置只保存不可逆的凭据引用，不保存密码正文。 |
| M2 | 持久化即密文 | 剪贴板正文、预览、文件名、URI、历史和缓存必须先经 AEAD 加密再写入 SQLite、App Group 或文件系统。 |
| M3 | 历史默认关闭 | 在加密历史完成前，移动端不得持久化历史；当前项仅允许加密、带 TTL 的最小缓存。 |
| M4 | 应用层端到端加密 | SyncClipboard v3 的 HTTP 路由形状可用于兼容，但业务载荷必须是 XChaCha20-Poly1305 密文；TLS 仅作为纵深防御。 |
| M5 | 一次性配对 | 二维码只携带短时、单次邀请和桌面端公钥，不携带可长期复用的用户名/密码。每台设备获得独立、可撤销的密钥。 |
| M6 | 防重放 | AEAD 的 AAD 至少绑定协议版本、方法、路径、设备 ID 和序列号；服务端校验唯一 nonce 与有效时间窗。 |
| M7 | 密钥边界 | 移动端安全关键逻辑由 Rust `uc-mobile` 核心通过 UniFFI 暴露；TypeScript 不自行实现加密协议或持有可长期复用的明文主密钥。 |
| M8 | 日志脱敏 | 日志、崩溃报告、遥测和通知预览不得包含剪贴板正文、密钥、密码、完整邀请或完整 token。 |

## 平台产品约束

### Android

- 商店版只提供分享菜单、Quick Settings Tile、通知动作和用户可见的前台同步流程。
- Shizuku、悬浮窗与 `READ_LOGS` 方案只能进入明确标识的高级侧载构建，不得成为默认路径。
- Android 10 及以上版本不承诺在应用不可见时静默读取系统剪贴板。

### iOS

- 不承诺静默后台监听系统剪贴板。
- 支持路径限定为分享扩展、快捷指令、组件/控制中心入口、通知动作和前台交互。
- App Group 只用于跨扩展交换密文与非敏感元数据；密钥必须留在 Keychain Access Group。

## 配对与消息封装目标

1. 桌面端生成短时、单次邀请，绑定桌面端公钥和允许的设备标签。
2. 移动端扫描邀请并生成设备密钥对；桌面端登记独立设备身份。
3. 双方通过认证密钥协商派生会话密钥，不传输长期可复用密码。
4. 每条剪贴板消息使用 XChaCha20-Poly1305 独立加密，并用 AAD 绑定上下文。
5. 撤销设备后拒绝其后续序列号；单 MasterKey v1 无法撤回已泄露历史的限制必须在界面中如实说明，DEK 信封分层留到 v2。

## 明确禁止

- Base64 伪装成“安全存储”或“加密”。
- 在 AsyncStorage、NSUserDefaults、App Group、SQLite 或普通文件中保存明文密码和业务载荷。
- 默认启用仅使用 Basic Auth 的明文载荷兼容模式。
- 通过中心服务器存储或转发剪贴板内容。
- 为追求“自动同步”而绕过 Android/iOS 的权限和后台执行边界。
